# LearnCloud Core Records Module — Build Plan
**HQ:** Bulawayo, ZW | **Frozen Base:** Multi-tenancy with tenant_id discriminator, BaseEntity audit + soft-delete, global query filter via reflection, ITenantContext, Permission handler `RequiresPermission`, JWT claims tid/uid/tv/ss
**Goal:** Students, Guardians, Staff, Classes/Streams, Subjects, Enrolment, Admissions — full three layers each, permission-checked, validated, audited, server-side list with search/filter/sort/pagination/CSV export, student detail with 7 tabs

---

## 0. ARCHITECTURE PRINCIPLES (From Previous Prompts)

- **Shared DB, tenant_id first index:** Every tenant-owned table `TenantId BIGINT UNSIGNED NOT NULL` leading index `idx_{table}_tenant_{field}` per `LearnCloudDbContext` reflection filter
- **BaseEntity:** Id, CreatedAt/By, UpdatedAt/By, IsDeleted bool, DeletedAt/By
- **TenantOwnedEntity : BaseEntity, ITenantEntity { TenantId }**
- **Global Query Filter:** Automatically applied by reflection in `LearnCloudDbContext.OnModelCreating` → `!IsDeleted && (IsExplicitNoTenant || TenantId==CurrentTenantId)`
- **Automatic TenantId assignment + guard:** SaveChanges throws if entity saved with TenantId != context (cross-tenant FK attack)
- **Audit Interceptor:** Captures old/new JSON, tenant, actor, ip, writes AuditLog tenant_id nullable
- **Permission Handler:** `[RequiresPermission("students.read")]` checks JWT perm claims or loads from DB if perms_hash ref, validates TokenVersion/SecurityStamp
- **Design System:** Tailwind tokens primary #0F153A, secondary #5F3F96, touch 44px, greyscale-legible

Core Records must reuse these — no new DbContext, extend existing `LearnCloudDbContext` with new DbSets.

**Proposed Build Sequence (Entity by Entity):**

**Phase 0 - Shared Kernel (I build first, quick):**
- Enums: StudentStatus (Applicant, Enrolled, Transferred, Graduated, Withdrawn, Archived), Gender, GuardianRelationship, EmploymentType, AdmissionStatus (Inquiry/Applied/DocsPending/Interview/Offered/Accepted/Rejected/Enrolled)
- Value Objects: AdmissionNumberPattern config {prefix, year, number, format e.g. {prefix}-{year}-{number:5}}
- Common DTOs: PagedRequest (page, pageSize, search, sortBy, sortDesc, filters JSON), PagedResult<T>, CsvExportDto
- Base validators: PagedRequestValidator

**Phase 1 - Subjects (Independent, no dependencies):**
- Foundation for Staff subjects taught
- Simple, good warm-up

**Phase 2 - Classes & Streams (Grade, Stream):**
- Grade: Name, Code, AcademicYearId, level_order
- Stream: GradeId FK, Name, full_name (Grade 5 Blue), capacity, class_teacher_staff_id (nullable FK Staff, set later), room_id, AcademicYearId/TermId
- Needed before Students (current enrolment) and Enrolment

**Phase 3 - Students (Core):**
- **Requirements:** admission number generated by configurable pattern {prefix}-{year}-{number:5} (stored in TenantSettings), personal details first/last, fullName computed, dob, gender, national_id, photo_url (5MB upload), current_enrolment_id FK Enrolment (latest), student_number unique per tenant, status with history table StudentStatusHistory, documents table StudentDocument (type birth cert, id, photo, file url, verification)
- **Status History:** Not column overwrite — separate table StudentStatusHistory student_id, from_status, to_status, reason, changed_by, date
- **Enrolment is NOT a column:** Student has current_enrolment_id for fast read but history lives in Enrolments

**Phase 4 - Guardians & GuardianStudentLink:**
- **Guardian:** Can be linked to several students, phone/email, contact preferences sms/email bool, address, occupation, user_id nullable for portal login
- **GuardianStudentLink:** Junction tenant_id, guardian_id, student_id, relationship_type mother/father/guardian..., is_primary_contact, is_billing_contact (one fee payer per student per year), is_emergency, can_pickup, academic_year_id
- Billing flag validation: only 1 is_billing per student per academic_year

**Phase 5 - Enrolment (History):**
- **Enrolment is a record linking student, class, stream, academic year and term — not column**
- Table StudentEnrolment: id, tenant_id, student_id, academic_year_id, term_id, grade_id, stream_id, enrolment_status enrolled/promoted/repeated/transferred_in/out/withdrawn/graduated/readmitted, enrolment_type new/repeat/transfer/readmission/continuing, previous_enrolment_id self FK, enrolment_date, exit_date, exit_reason, is_current bool (only one true per student)
- Past year retrievable: query Enrolments where student_id and academic_year_id, never overwrite
- Handles repeat (same grade new year), transfer stream (same year new stream), leave and return (readmission)

**Phase 6 - Staff:**
- Employment details, staff_number configurable pattern, first/last, employment_type permanent/contract/part_time, qualification, national_id, hire_date, status active/inactive
- Subjects taught M2M StaffSubject (staff_id, subject_id)
- Classes assigned via TimetableSlot or StaffClassAssignment (staff_id, grade_id, stream_id, subject_id, academic_year_id)
- Class teacher assignment: Stream.class_teacher_staff_id FK Staff
- Linked user account: user_id nullable FK Users (one-to-one)

**Phase 7 - Admissions:**
- Application pipeline: Inquiry, Applied, DocsPending, Interview, Offered, Accepted, Rejected, Enrolled (converted)
- Applicant retained but never counted in enrolment figures: Admission entity separate, converted_student_id nullable, status, interview_date, offer_date, guardian snapshot, documents_json, notes, academic_year_id, desired_grade_id, converted_enrolment_id
- Conversion creates Student + Enrolment in transaction

## 3. SPECIFIC REQUIREMENTS MAPPING

| Requirement | Implementation |
|---|---|
| Admission number generated by configurable pattern | `TenantSettings.admissionNumberPattern` JSON {prefix, year, number length} e.g. `{prefix}-{year}-{number:5}`. Service `AdmissionNumberGenerator` uses atomic `admission_number_counters` table tenant_id, year, last_number FOR UPDATE to avoid duplicates. Preview in form. |
| Personal details, photo, current enrolment | Student entity first/last, dob, gender, national_id, photo_url (upload 5MB), current_enrolment_id FK Enrolment nullable for fast read, but history authoritative from Enrolments table |
| Guardian links with relationship and billing flag | GuardianStudentLink junction tenant_id, guardian_id, student_id, relationship_type, is_primary_contact, is_billing_contact (one fee payer per student per academic_year validated in service), is_emergency, can_pickup, academic_year_id |
| Status (applicant, enrolled, transferred, graduated, withdrawn) with status history | StudentStatusHistory student_id, from_status, to_status, reason, changed_by, changed_at. Service creates history on every status change, never overwrites. List endpoint GET /students/{id}/status-history |
| Documents | StudentDocument student_id, type birth_cert/id/photo/other, file_url, file_name, file_size, verification_status pending/verified/rejected, uploaded_by |
| Enrolment is record not column, past year retrievable | StudentEnrolment table, is_current bool only one per student, previous_enrolment_id self FK, enrolment_type new/repeat/transfer/readmission. Query history `WHERE student_id=X ORDER BY academic_year_id, term_id`. Current enrolment via `current_enrolment_id` for speed but history authoritative. |
| Guardian can be linked to several students; one flagged fee payer | Guardian entity separate, GuardianStudentLink many-to-many. Validation: service ensures only 1 is_billing per student per academic_year: `SELECT COUNT(*) WHERE student_id=X AND academic_year_id=Y AND is_billing=1` must be <=1. Deduplicate by phone/email when linking. |
| Contact preferences SMS/email | Guardian.sms_opt_in bool, email_opt_in bool, ContactPreferences JSON |
| Staff: employment details, subjects taught, classes assigned, class teacher assignment, linked user account | Staff entity staff_number pattern, employment_type enum, qualification, national_id, hire_date, status. StaffSubject M2M, StaffClassAssignment, Stream.class_teacher_staff_id FK Staff, UserId nullable FK Users (creates user invite) |
| Admissions: application, review, offer, acceptance, conversion, applicant retained but never counted | Admission entity status enum Inquiry/Applied/DocsPending/Interview/Offered/Accepted/Rejected/Enrolled, desired_grade_id, interview_date, offer_date, converted_student_id nullable, converted_enrolment_id nullable, documents_json, notes, guardian snapshot. Conversion transaction creates Student+Enrolment+StatusHistory. List for enrolment figures excludes admissions: count from Students where status enrolled, not from Admissions |
| Every list: server-side search, filter, sort, pagination, CSV export | Common PagedRequest: page, pageSize 25/50/100, search (name/number/email), filters dict (grade, stream, status, academicYear, gender), sortBy (name, number, created_at), sortDesc. Controller GET list calls service with tenant filter + IsDeleted false + search ILIKE %term% (tenant_id leading index), filter, sort, pagination Skip/Take, total count. CSV export endpoint GET /export returns File CSV with same filters. Uses `idx_{table}_tenant_{field}` indexes. |
| Every mutation: permission-checked, validated, audited, soft-deleting | Permission-checked: `[RequiresPermission("students.write")]`, `students.read`, `students.delete`, `guardians.write`, `staff.write`, `enrolments.create`, `admissions.convert` etc. Validated: FluentValidation. Audited: AuditInterceptor captures old/new JSON, tenant, actor, ip. Soft-deleting: IsDeleted true, DeletedAt/By, global filter hides |
| Student detail page tabs | React StudentDetail.jsx Tabs: profile, guardians, enrolment history (timeline repeat/transfer), attendance summary (calls attendance module), fees (invoices for student), results (report cards), documents (upload/view). Each tab lazy loads. |
